# House Hub — instructions for Claude

The Anderson family's one-stop app, used on iPad, iPhone and desktop. This file is the map; read it before touching anything.

## Where things run

| Piece | Where | How it deploys |
|---|---|---|
| Site (`index.html`, `apps/`, `sw.js`, `offline.html`, `icons/`) | **GitHub Pages**, `main` branch, repo root → https://vantrix117.github.io/house-hub/ | `git push` — Pages rebuilds in 30–90 s. Always confirm the live file returns 200 before saying it is live. |
| API + database | **Cloudflare Worker `house-hub-api`** + **D1 `house-hub`** → https://house-hub-api.catalystfarm1.workers.dev | `cd worker && npx wrangler deploy`. Editing `worker/` changes nothing until you deploy. Full reference: [`worker/README.md`](worker/README.md). |
| Secrets | Cloudflare Worker secrets: `VAPID_PRIVATE_KEY`, `ANTHROPIC_API_KEY` | `npx wrangler secret put NAME` from `worker/` — it prompts. **Never write a secret, a PIN or the pairing code into this repo, a `.dev.vars` you commit, or a chat transcript.** |

There is no build step, bundler, framework or `package.json` anywhere. Do not add one. The Worker is plain ESM that wrangler bundles; it has no npm dependencies.

## How the hub works

- **Pairing + profiles.** A device is paired once with the household pairing code (hash in D1 `settings`; wrong codes are limited per device install id `hub.fp` and, looser, per IP). Then each person picks their profile: kids and the kiosk open on tap, adults create a 4–8 digit PIN on first tap and use it afterwards (Me → Change my PIN, `POST /api/me/pin`). After an admin **Reset PIN** the person first types the **one-time 6-digit code** the admin was shown (24 h), then chooses a new PIN — no other device can claim the account meanwhile; resetting an admin (your own or a co-admin's) needs the resetting admin's PIN. Wrong PINs and codes are counted before they are checked and limited per device (5 per 15 min, 20 a day) and per profile across all devices (10 an hour, then a pause of 1 h doubling to 24 h, and a push to the admin); a device the person has signed in on before is never held by that pause. The admin's own row offers Change PIN, not a reset. Tokens live in `localStorage` (`hub.device`, `hub.session`) and are shared by every app on the origin.
- **The Kitchen device** (KITCHEN-1, `migrations/006-kitchen.sql`). The admin marks one paired device as the kitchen from another device: Me → Admin → Devices → "Make it the kitchen" / "Not the kitchen", confirmed with the admin's PIN (`PUT /api/admin/devices/:id/role {role, admin_pin}`; the kitchen itself has no way into admin). It then signs in only as the `kitchen` profile (kind `kitchen`, no PIN; the shell asks `GET /api/device` at boot and after any 401, so it never shows the picker), and no other device can sign in as the kitchen. It writes the family apps (Larder, family prayer list, reminders; its own Timer and Tally rows) and nothing personal: no private lists, F260, Verses, chat, push or admin. When it credits someone (a name in `prayedBy`, the Larder's `finishedBy`, a feed line via `hub.activity(text, app, { as })`, an album photo `as`) that must be a household member, never a kid on the Larder. The kitchen is not a person: pickers and `hub.people()` leave it out, and the admin can change only its colour. **Its shell** (KITCHEN-2, batch 2a): no picker (offline, a device that was the kitchen waits on "Waiting for the house" instead), no Me or Chat tab (`#me`/`#chat` land on Home), the Apps list is the Larder, Prayer (the family list only), Timer and Tally, and Home is `renderKitchenHome()` in `index.html`: the clock, every running timer in the house (batch 6, GAP-HOME-1: the family mirror `run:<owner>:<id>`, each with its owner's face and the time counting in place; Pause / Resume / Stop only on the kitchen's own, everyone else's read-only), food to eat soon, today's family prayers with the faces of who prayed, reminders (add; clear with Undo, removed for everyone after 6 s like Home's) and the family album with Add, in glance-size type (`--fs-glance-*`), repainted in place. **Who gets credit**: `hub.whoDidThis({ who: 'household' | 'adults', title, message })` → the tapped person or null — a sheet of the household's faces, no PIN (attribution, not a sign-in; never guests, the TV or the kitchen). Prayer's Prayed (and a prayer-mode run, asked once) shows everyone, kids included, and ticks that person's id; the Larder's ✓ and the album's Add show the adults only (P5-D2) and send `finishedBy` / `{as}`. ## Adding an app

1. **Write `apps/<id>.html`, self-contained.** All CSS in `<style>`, all JS in `<script>`, no external scripts, no CDN, no fonts fetched over the network (Prayer used to fetch Google Fonts; since audit batch 1 it uses the system fonts like everything else). Must open standalone *and* inside the hub's iframe.
2. **Import the shared pieces:**
   ```html
   <script>/* the pre-paint bootstrap: audits/tools/phase4/tokens/bootstrap.js, pasted exactly, right after the viewport meta */</script>
   <link rel="stylesheet" href="design.css">
   <script src="hub.js" data-app="<id>" data-scope="person"></script>   <!-- person | family | both -->
   <script>
   (async () => {
     await hub.ready();                                 // profile + cached data are ready; pulls in the background
     const n = hub.get('count', { default: 0 });        // hub.set(key, value) · hub.remove(key) · hub.list('item:')
     hub.onChange(render);                              // another device changed something
     hub.activity('Counted to ' + n);                   // shows in the family feed on Home
     hub.migrate([{ from: 'oldLocalStorageKey', to: 'count' }]);   // optional, once per device, adults only
   })();
   </script>
   ```
   Keys: `[A-Za-z0-9_.:-/]`, ≤ 200 chars. For lists use `item:<id>` rows and `hub.list('item:')`. Check `hub.canWrite` (false for the kiosk) before offering edits. `hub.voiceInput(text => …)` gives speech-to-text where the browser supports it. `hub.toast(msg, ms, { action: 'Undo', onAction })` shows a toast with one button; `await hub.confirm(message, { title, ok, cancel, danger })` asks in the shared confirm sheet (true only from its confirm button or Enter; Cancel, Escape and the backdrop give false) and `hub.alert(message, { title })` is its one-button notice — never the browser's `confirm()`/`alert()`/`prompt()`; `hub.onLeave(fn)` runs `fn` just before the SDK's send on pagehide (a write made on the way out goes with it). `hub.immersive(true)` (batch 3, UX-PRAYER-9) asks the hub's viewer to hide its top bar so the app has the whole screen, and `hub.immersive(false)` brings it back; standalone it does nothing and returns `false`. An app that uses it keeps its own visible Close (≥ 44 px) that calls `hub.immersive(false)`, and handles Escape (calling `preventDefault()` when it closes something itself; an Escape it leaves alone brings the bar back). When the shell brings the bar back by itself (Escape in the shell, the viewer closed) the app gets `hub:immersive` on `window` with `detail.on === false`; `hub.isImmersive()` reads the state. `hub.profile` is `{id, name, kind, isAdmin, isGuest, color, hue, emoji}` (`hub.hueOf(p)` gives anyone's colour family).
3. **Register it in `apps.json`** — one entry, valid JSON, no trailing commas:
   ```json
   { "id": "chores", "name": "Chore board", "file": "apps/chores.html", "color": "#5B6FA8", "hue": "lagoon", "icon": "icons/chores.svg", "scope": "family", "tile": "small", "visibleTo": ["eli", "christian"] }
   ```
   `scope` must match `data-scope`. `hue` is the app's colour family (one of the nine app families of decision D5: coral, apricot, honey, pistachio, leaf, seafoam, lagoon, cornflower, orchid; the tile, its Home card head and every icon of the app carry it as `data-accent`; `color` stays for older copies). `tile` is `small` or `wide` (wide tiles can render a widget in `index.html` → `widgetHtml`). `visibleTo` (profile ids) hides the app from everyone else — omit it for all. Guest profiles (Me → Add a guest) are never listed: a guest sees every app whose `visibleTo` is unset or includes any household adult id (`index.html` visibleApps and `POST /api/chat` apply that rule). `icon` is an SVG file in `icons/` (duotone: a `class="duo"` path plus stroke paths, `currentColor`), or an emoji if you must. `"dark": true` darkens the viewer while loading. Icons INSIDE an app come from the one shared sprite `icons/sprite.svg` (audit batch 4: Lucide geometry, ISC, listed in `icons/LICENSE-lucide.txt`; one weight `--icon-stroke`, sizes `--icon-*`): `<svg class="sym" aria-hidden="true"><use href="../icons/sprite.svg#i-<name>"/></svg>` beside a visible word (design.css's component half styles `svg.sym`); draw a missing glyph into the sprite in Lucide's style, never an emoji or a text glyph as an icon, and keep one drawing per meaning (04-design-system.md, Table ICON-6). The sprite is precached in `sw.js`.
4. **Give it art.** Add a spot illustration `art/app/<id>.svg` (200×160) in `scripts/make-art.mjs` and re-run it — the Home cards, empty states and the style guide pick it up from there; `scripts/test-art.mjs` fails until every app has one. See [`art/README.md`](art/README.md).
5. **Precache it** by adding the file, its icon and its art to the `SHELL` list in `sw.js`, then `node scripts/bump-sw.mjs` (bumps `VERSION` and checks the list). Skip precaching anything multi-megabyte (add it to the skip list in that script).
6. **Touch-first, all devices.** 44×44 px minimum targets (60 px+ for primary actions), no hover-only or right-click-only affordances (hover styles only under `@media (hover: hover) and (pointer: fine)`), Enter/Escape on inputs and dialogs, works from ~375 px to ~1400 px wide with no horizontal scroll, `viewport-fit=cover` with safe-area insets on edge-anchored controls, `localStorage` reads/writes in `try/catch`.
7. **Commit, push, verify live:** `git add apps/<id>.html apps.json icons/<id>.svg sw.js && git commit && git push`, then poll `https://vantrix117.github.io/house-hub/apps/<id>.html` until it returns 200 and confirm `apps.json` on the live site has the entry. Report that result, not just "pushed".

Legacy `localStorage` data goes to the **first adult** who opens the app on a device; kids never receive migrated data.

## Adding a chat tool

All in [`worker/src/chat.js`](worker/src/chat.js):

1. Add the tool definition to `TOOLS` (`name`, `description`, JSON-Schema `input_schema` with `additionalProperties: false`). Keep descriptions short and concrete — the model reads them.
2. Handle it in `runTool()`: validate the input yourself, respect `profile.kind` (kids: nothing on adult-only apps; kiosk never reaches chat), write through `putOne()` from `data.js` so the normal sync rules apply, call `activity()` so it appears on Home, and return `{ ok, result, chip }`. `result` goes back to the model (keep it small); `chip` is the human line shown in the Chat tab (`"✓ Added milk to leftovers"`) — `null` for read-only tools.
3. Mention the new capability in `systemPrompt()` if the model needs a hint about when to use it.
4. Test without a key: `node scripts/mock-anthropic.mjs` + `ANTHROPIC_BASE_URL="http://127.0.0.1:8791"` in `worker/.dev.vars` (git-ignored), teach the mock a trigger phrase, then `scripts/smoke-chat.sh http://127.0.0.1:8787 <local-code>`. Deploy with `npx wrangler deploy`.

## Push reminders

- Keys: `VAPID_PUBLIC_KEY` and `VAPID_SUBJECT` are vars in `worker/wrangler.toml`; `VAPID_PRIVATE_KEY` is a secret. Regenerate the pair with `web-push`'s `generateVAPIDKeys()` if it ever leaks (everyone must re-enable notifications afterwards).
- Schedule: `[triggers] crons = ["*/15 * * * *", "* * * * *"]` (audit batch 2b; the minute trigger since batch 6). The minute trigger runs only `timerJob` ("Timer done" to the owner of a `timer:<id>` row — or a legacy `timer.active` — that ended in the last 10 minutes and was not stopped, once per start and end, remembered in `settings.timer_pushed`; it also clears rows ended more than 10 minutes ago and their mirrors, the 10-minute rule; at the top of each hour it deletes the Timer's tombstones older than 30 days, and it reads through the partial index of live Timer rows from `migrations/008-timer-live.sql` — run it with the 006/007 migrations at deploy; without it the job reads the whole Timer range); the 15-minute one runs the jobs below and never the timer. `jobsAt()` in [`worker/src/reminders.js`](worker/src/reminders.js) reads the New York time of the firing (`event.scheduledTime`): every firing of the 8 am hour runs `morningJob` (leftovers 5+ days old → household adults) and `prayerJob`; of the 8 pm hour `behindJob` on Sundays (guests too: it is their own reading), `prayerJob` and `prayedForJob` — so a push that failed at :00 is tried again at :15, :30, :45; every firing runs `eveningJob` (no F260 reading logged today → that person, in the hour of their `push_pref:readAt`, 8 pm unless they chose another; a forced run ignores the times), `parkJob` and `prayTimeJob` (the chosen time's whole hour is eligible). The guest clean-up and the kids' 90-day chat clean-up ride on the first 8 am / 8 pm firing. Morning, evening, behind, praytime and prayedfor send at most once per person per day (delivered pushes only); prayer and park remember in `settings` (`last_prayer_push_at`, `park_alerts`) what each person has been told. Dead subscriptions are deleted; per-person toggles come from `app_data(person, hub, 'push_pref:<kind>')` over the old `push_prefs` row (`prefsFor`, `mergePrefs`).
- To add a reminder type: write a `xJob(env, now)` next to the others, add it to `JOBS` and to `jobsAt`, add a toggle in the Me tab (`renderNotif` in `index.html`) that writes the row `push_pref:x`, and log with `pushTo(env, profileId, 'x', payload)`.
- Test: `npx wrangler dev --test-scheduled` and `curl "http://127.0.0.1:8787/cdn-cgi/handler/scheduled?cron=*/15+*+*+*+*"` (what runs depends on the real clock; `cron=*+*+*+*+*` runs the timer job alone), or force a job with `POST /api/admin/cron/run {"job":"morning"}` as the admin. `scripts/push-receiver.mjs` stands in for the push service and decrypts what the Worker sent. `scripts/test-push.mjs` checks the encryption against the RFC 8291 test vector.

|---|---|

| Add or remove a household person, add or hand over an admin | Me → Admin → Household (each asks for your PIN; `POST /api/admin/profiles`, `POST /api/admin/profiles/:id/remove`, `PUT /api/admin/profiles/:id/admin`) |

| Unpair a lost device | Me → Admin → Devices → Unpair |
| Chat/push usage | Me → Admin → Usage (30 days, by New York day — the chat limit's day), or `GET /api/admin/usage` |
| Schema changes | Add an idempotent migration under `worker/migrations/`, run it with `npx wrangler d1 execute house-hub --remote --file …`, keep `schema.sql` in sync |
| Everything broken | Curl `/api/health`; `npx wrangler tail` for live logs; the SDK falls back to its local cache and shows a grey/red dot in the tab bar |
