## The pre-existing `scripts/screens-apps.mjs` failure: Tally's page background

Reported in `audits/06-implementation.md:1811` and `:2014` ("90/1 before and after... the one failure, Tally's page background"), `:2205` ("found, not fixed ... batch 11"), b8-report.md:18.

**The assertion** (`scripts/screens-apps.mjs:93-96`): after the per-theme screenshots it samples `getComputedStyle(document.body).backgroundColor` with `data-theme=midnight`-ish (the last theme set, graphite, line 85-90) as `dark`, then sets hearth/light and samples again as `light`, and at 390 wide requires `dark !== light` ("`tally: page background changes between forest and hearth (${light} -> ${dark})`"). (The message says forest; the loop's last theme is graphite, `THEMES` :33; irrelevant.)

**Why Tally fails:** `apps/tally.html:34` is `background: var(--wash), linear-gradient(170deg, var(--bg) 0%, var(--accent-wash) 38%, var(--accent-fill) 100%);`. The shorthand has two image layers and **no colour layer**, so the computed `background-color` is `rgba(0, 0, 0, 0)` in every theme: `dark === light`, the assertion fails. The palette really does reach the page (the gradient starts at `var(--bg)`; screenshots differ, VIS-TALLY-11), but the test reads only `background-color`. Every other app inherits `design.css:836` `body.ds { background: var(--wash), var(--bg) }` (a colour layer, `--bg`) and passes, including Timer.
**Fix (one line, Tally):** add a final colour layer to :34, `... var(--accent-fill) 100%), var(--bg);` (the same shape as design.css:836; keeps `background-attachment: fixed` :35). It also gives the page a solid fallback if a gradient fails. No visual change (the colour layer sits under both images). **Check:** `node scripts/screens-apps.mjs <code>` -> 91/0 (was 90/1); `getComputedStyle(document.body).backgroundColor` differs between hearth and graphite/midnight. Do not change the script.
